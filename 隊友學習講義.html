先讀簡版介紹：掌握作品想解決的問題與定位

docs/官方文件-簡版介紹.md
核心一句話：我們不是下一個 591，也不是主觀評論網。我們是協助學生與初次租屋者的「租屋資訊整理與風險判讀工具」。
  • 核心痛點：租屋資訊極度散落（刊登頁、房東LINE口頭說法、紙本合約條款、看房筆記），且資訊嚴重不對稱，新手常看不到致命風險。
  • 主要對象：學生、社會新鮮人、第一次租屋者。
  • 兩大核心架構：
    • RHIR（租屋資訊交換格式）：把雜亂資訊整理成統一欄位，明確標記「已揭露、未揭露、來源」。
    • RRI（租屋風險指數）：用固定規則算出五個面向的風險參考，指出缺漏與疑點。
重要界限：本系統「提供判讀參考與待追問清單」，絕不替使用者決定要不要租，也不提供法律保證或安全背書。

再讀 README：認識目前功能與外部依賴

README.md

程式碼已經寫好很多路徑，但展示時請務必分清楚「本機可跑」與「需要聯網/外部服務」：

✅ 本機獨立流程（瀏覽器即可驗證）
  • 租屋表單輸入與欄位完整度即時檢核
  • RHIR JSON 結構化預覽、複製與下載
  • RRI 固定規則五面向計算與區間顯示
  • 本機物件紀錄與版本歷史（localStorage）
  • 白話風險報告與待追問清單產出
⚠️ 外部依賴流程（需網路與 API Key / 雲端）
  • AI Insight / 個人策略顧問：需 OpenRouter 金鑰與聯網
  • 案例庫檢索：需 Supabase 資料庫連線與可用數據
  • 契約上傳與 OCR 解析：需雲端儲存與解析服務
  • Chrome 擴充插件：需手動載入未封裝擴充功能
快速本機跑起來：npm install ➔ npm run dev ➔ 瀏覽器開 http://127.0.0.1:5500 即可操作。

讀計畫書重點段落：專案摘要、技術可行性與成果

專案計畫書.md
1. 專案摘要 (第 48-66 行) 以 RHIR 整理資料、以 RRI 計算風險，透過 AI 產生白話報告與「待追問清單」，讓簽約前能更早看見問題，降低不對稱。
2. 解決方案 (第 230-379 行) 打造單一物件的風險評級，將不確定性量化。資訊不足時不隱瞞，直接以「風險區間」標示不確定性。
3. 技術可行性 (第 384-403 行) 採前端 MVP 先行，不碰龐大的平台媒合與房源爬取，先把「單一物件能不能看懂」做深做紮實。最小展示路徑：表單 ➔ RHIR ➔ RRI ➔ 報告。
4. 目前成果與未來 (第 562-591 行) 已具備多頁面流程、RHIR 產生器、RRI 計算與桌面版指令。未來規劃為收斂決賽展示、驗證數據真實性，公開資料大串接保留為長期願景。
永續指標連結：主要呼應 SDG 11.1（安全、適足且可負擔住宅），讓安全與權益成為決策維度，而非只看價格。

看 MVP 規格現況：五大風險面向與驗收提醒

docs/Rent-Unfiltered-MVP版本規格.md

目前 RRI 規則引擎專注於以下五個核心面向：

1. 契約透明度 合約審閱期、修繕責任切分、提前解約違約金、自然折舊責任。
2. 費用透明度 電費計價是否符合台電規範、公共電費分攤、水費、管理費明細。
3. 居住安全 頂樓加蓋/違建、滅火器、火災警報器、熱水器通風環境、逃生動線。
4. 租客權益 能不能報稅（租金扣除額）、能不能遷戶籍、能否申請租屋補助。
5. 生活適配度 隔音、採光通風、寵物約定、生活機能與個人生活習慣相容性。
⚠️ 關鍵提醒（千萬別在評審面前講錯）：
「程式碼寫好 ≠ 現場已完成驗收」！我們系統內放的租屋物件是「示範模擬資料」，絕不能宣稱為真實訪談或市場普查統計；若展示時遇到網路異常，請果斷切回本機核心路徑（表單 ➔ RHIR ➔ RRI）。

最後閱讀兩份背景：創作理念 vs 決賽版本目標

docs/創作理念與動機.md · docs/Rent-Unfiltered-決賽版本規格.md
📖 為什麼做這件事？（創作理念）

在經濟學上，租屋是在消費「居住服務」。自住者有餘裕做大量調查，但學生、新鮮人承擔能力弱、搜尋成本高，常淪為資訊弱勢。

"Unfiltered" 的意義：不被廣告、流量、房東話術與平台權力所過濾，將真正攸關安全的條件攤在陽光下。

🎯 決賽版本規格的正確理解方式

文件中的「最終版本樣貌」（如多 Agent 深度協作、全自動跨平台比價、大規模政府資料即時對接）是長期的產品願景。

切記：不要把願景當成「現在已經做完的功能」！跟評審交流時要明確切分「現有 MVP 成果」與「未來藍圖」。
